# Canvas UI 设计审计

日期：2026-08-05
范围：`public/canvas.html`、`public/canvas.js`、`public/canvas.css` 以及现有画布交互测试。
模式：Operate。画布的首要任务是让用户快速看懂节点关系、配置生成模块并判断任务状态。

## 结论摘要

当前画布的核心能力是完整的，但视觉系统经过多轮迭代后出现了“同一模块多套规则并存”的问题。最影响使用的不是功能缺失，而是缩放没有边界和显式控制、媒体节点的视觉层级不统一、图片与视频生成状态的语言和动效不一致。

本轮已经落地：

- 缩放限制为 25%–250%，增加缩小、放大、1:1 重置控件。
- 缩放控件支持键盘 `+`、`-`、`0`，并保持滚轮/触控板指针锚定。
- 图片与视频节点统一为“透明外壳 + 预览面 + 输入面”的结构，减少重复卡片、渐变和毛玻璃叠层。
- 图片生成状态改为与视频一致的“生成中 / 动态进度条 / 模型名 / 任务信息”层级。
- 新增 `scripts/canvas-viewport-controls.test.mjs` 回归测试。

本轮未部署线上服务。

## 关键问题

### P1：缩放没有上限，也没有明确恢复路径

- 位置：`public/canvas.js` 的 `clampCanvasScale()`、`zoomCanvasAt()`；原控件只有 `#canvasZoomReadout`。
- 类别：交互、响应式、可访问性。
- 影响：用户可以把画布放大到遮挡工作区，也可以缩小到几乎不可见；出现误操作后只能反向滚轮恢复，键盘用户没有入口。
- 修复：增加 25%–250%边界、中心锚定的缩放按钮、1:1 重置和 `+ / - / 0` 快捷键；边界按钮禁用但保留状态可见。

### P1：媒体节点承担了过多容器职责

- 位置：`public/canvas.css` 中多组 `.canvas-node.video-node`、`.video-preview-slot`、`.video-composer` 和 `.image-node` 覆盖规则。
- 类别：视觉层级、实现完整性、性能。
- 影响：预览窗口、编辑器外壳和参数区在不同迭代中重复提供背景、边框、阴影和圆角，导致“模块很重”、选中态不稳定，也增加后续改动误伤的概率。
- 修复：把节点外壳降为透明布局锚点，预览和输入面各自承担一次视觉分组；本轮以统一石墨色表面和单一焦点反馈覆盖最终生效规则。

### P1：图片和视频的生成状态不一致

- 位置：`renderImagePreview()`、`renderVideoPreview()`。
- 类别：状态反馈、可理解性。
- 影响：图片曾显示“处理中”静态条，视频显示“生成中”动态条；用户无法用同一套视觉规律判断任务是否仍在运行。
- 修复：两类任务统一“生成中”主标签、动效进度轨、模型名和辅助任务信息；`prefers-reduced-motion` 下仍保留静态进度和状态文本。

### P2：CSS 规则重复，最终样式难以维护

- 位置：`public/canvas.css` 约 4,800 行以后多轮媒体模块覆盖。
- 类别：实现完整性、主题一致性。
- 影响：修改一处样式可能被文件后段的选择器覆盖，排查“为什么线上没变化”成本高。
- 建议：下一轮建立媒体节点 token 和单一最终块，删除已失效的旧规则；每次 UI 变更配套静态断言，避免继续堆叠 override。

### P2：窄屏工作区仍缺少真实渲染验证

- 位置：`.video-node`、`.image-node` 的固定编辑器尺寸与 `@container` 规则。
- 类别：响应式。
- 影响：侧边 Agent 打开、浏览器窗口较窄或系统字体放大时，输入面与参数条可能挤压。
- 建议：用 1280、1024、768 三档视口做一次批量截图验证；节点本身保持固定工作区尺寸，但应允许参数条分两行并避免水平溢出。

## 当前正向发现

- 画布连线在 SVG 内部 group 缩放，且使用 `vector-effect: non-scaling-stroke`，不同缩放级别下线宽稳定。
- 平移使用 `requestAnimationFrame` 合并更新，视口移动期间避免重新加载视频媒体，已经针对白色色块和视频消失做过保护。
- 视频轮询更新状态时尽量复用现有 `<video>`，只有媒体身份变化才重建，能减少频闪。
- 节点连接点和媒体操作已有 aria-label、原生控件和上下文菜单入口，适合继续补键盘路径。

## 设计原则

1. 画布背景是工作空间，不是装饰面；节点必须在黑色网格上快速被识别。
2. 节点外壳只负责布局和拖拽，预览面负责内容，输入面负责编辑，三者不重复表达同一层级。
3. 生成状态只保留一个主要动效焦点：进度条；模型名和任务信息只做辅助阅读。
4. 缩放是视口状态，不改变节点自身尺寸；所有缩放入口共享同一套边界和持久化逻辑。
5. 选中、聚焦、运行、失败必须有可区分但克制的状态，不依赖颜色单独传达含义。
