# 两端协作打通方案(本机 Claude + 另一台 Codex)

## 现状与目标
- **现状**:两台电脑(本机 Claude、另一台 Codex)都改同一项目、都 SSH 到同一台生产
  `101.42.111.251` 各自 scp 盲覆盖 → 今天已多次互相删功能、生图卡死。
- **两边都用同一个 GitHub 私有仓库** `Wangchao0905/pixeltoy`。
- **目标**:GitHub 立为唯一中枢。改动先 push,生产用 `git pull` 部署。杜绝盲覆盖。

## 已探明的技术前提
- 生产有 git 2.43,能连 GitHub,但**无认证凭据、无 SSH key、当前不是 git 仓库**。
- 仓库是**私有**的(需认证才能 pull)。
- GitHub 仓库刚已同步为线上真实运行版(commit 979ef45)。

## 方案:只读 Deploy Key + 一键部署脚本

### 第 1 步:给生产配只读 Deploy Key(你需在 GitHub 操作一次)
1. 我在生产生成一对 SSH key(`~/.ssh/id_ed25519`,仅用于拉这个仓库)。
2. 我把**公钥**打印出来给你。
3. **你**去 GitHub → 仓库 Settings → Deploy keys → Add deploy key,粘贴公钥,
   **不勾** "Allow write access"(只读,生产只能拉不能推,更安全)。
4. 我在生产验证 `git ls-remote` 能通。

### 第 2 步:把生产变成 git 工作副本(不动运行中的数据)
风险控制:生产有大量 git 不该管的数据(projects/outputs/密钥/canvas-states/.bak)。
做法**不重新 clone**(那要先挪走整个目录、风险大),而是**原地初始化**:
1. `git init` + 关联 remote(用 Deploy Key 的 SSH 地址)。
2. 放入与仓库一致的 `.gitignore`(已在仓库里,含排除 projects/outputs/密钥/大媒体)。
3. `git fetch` + `git reset --mixed origin/main`:让 git **认得**所有已跟踪文件的版本,
   但**不改动工作区任何文件**(--mixed 只动索引不动文件)。
4. `git status` 核对:工作区应"干净或仅少量真实差异",数据/密钥都被 ignore。
   - ⚠️ 若生产某跟踪文件与仓库不一致(比如 Codex 刚 scp 了新版还没 push),会显示为改动
     → 那说明有未入库的线上改动,**先让那边补 push**,不能直接覆盖。

### 第 3 步:装一键部署脚本 `deploy.sh`(放仓库,生产可用)
```sh
#!/usr/bin/env bash
set -euo pipefail
cd /home/ubuntu/apps/pixel-toy
echo "== 拉取 =="; git fetch origin main
LOCAL=$(git rev-parse HEAD); REMOTE=$(git rev-parse origin/main)
[ "$LOCAL" = "$REMOTE" ] && { echo "已是最新"; exit 0; }
# 有本地未提交改动(scp残留)→ 停,别覆盖
if [ -n "$(git status --porcelain -uno)" ]; then
  echo "✗ 生产有未提交改动(可能是直接scp的),先处理再部署:"; git status --porcelain -uno; exit 1
fi
echo "== 备份 =="; mkdir -p .deploy_bak && cp server.js .deploy_bak/server.js.$(date +%Y%m%d-%H%M%S)
echo "== 更新 =="; git reset --hard origin/main
[ package-lock.json -nt node_modules ] && npm ci --omit=dev || true
node --check server.js
echo "== 重启 =="; pm2 restart pixel-toy --update-env
sleep 3; curl -fsS -o /dev/null http://localhost:4317/ && echo "✓ 健康" || { echo "✗ 健康检查失败"; exit 1; }
```
- 关键:脚本**检测到生产有未提交改动(scp 残留)就中止**,逼大家走 git,从机制上堵死盲覆盖。

### 第 4 步:两边的协作约定(写进仓库 CONTRIBUTING/README)
- 改动流程:本地改 → `git pull --rebase`(先同步对方) → 提交 → `git push` → SSH 生产跑 `./deploy.sh`。
- **不再直接 scp/rsync 覆盖生产**。谁 scp,`deploy.sh` 下次就会拦住报错。
- 两台电脑各自 `git pull --rebase` 保持同步;冲突在本地 git 层解决,不在生产上撞。

## 风险与回滚
- 全程**不删生产数据**(projects/outputs/密钥被 .gitignore,git 不碰)。
- 第 2 步 `git reset --mixed` 不改文件,零风险;真正改文件是第一次 `deploy.sh` 的 `reset --hard`,
  之前已 cp 备份 server.js,且此刻 origin/main = 当前线上版(979ef45),reset 到它 = 无变化。
- Deploy Key 只读:即使泄漏也只能拉、不能改仓库。

## 需要你做的两件事
1. 第 1 步第 3 点:GitHub 加 Deploy Key(我给你公钥)。
2. 告知另一台 Codex:改用 git push + `./deploy.sh`,停止 scp。(我可另写一份给 Codex 的说明)

## 不做
- 不做自动拉取/webhook(你已排除;自动上线风险高)。
- 不动生产的 projects/outputs/密钥/canvas 数据。
- 本次不改任何业务代码。
