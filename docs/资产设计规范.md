# 资产设计规范

> 面向创作者的资产描述撰写规范。照此写,系统能确定性识别 人物 / 场景 / 道具 / 插入 四类资产,
> 生成的参考图质量稳定、分类不出错。本规范的格式规则均经真实解析器验证。
>
> 配套:①解析器技术细节见 [asset-document-spec.md](./asset-document-spec.md);
> ②万一分类仍有偏差,解析后可在界面**拖拽纠偏**(见第六章)。

## 一、四类资产的定义与边界

| 类型 | 定义 | 典型 | 边界(别混) |
|---|---|---|---|
| **人物 Character** | 有身份的人/角色/生物,画面主体是"谁" | 主角、反派、配角、有名字的动物/怪物 | 群众演员不单列;地点不是人物 |
| **场景 Scene** | 地点/空间/环境,画面里**不含主要人物** | 安全屋、厨房、街道、实验室 | 只作空间参考;有人物的画面归到人物或分镜 |
| **道具 Prop** | 可持握/摆放的物件,白底参考 | 手机、武器、钥匙、文件 | 场景里的固定建筑不是道具 |
| **插入 Insert** | 插入镜头/证据细节特写,微距 | 按钮特写、屏幕文字、伤口、指纹 | 强调"特写/细节",不是完整道具展示 |

**分类第一原则:靠"段归属",不靠名字猜。** 把资产写在哪个类型段里,它就是哪类。
名字长得像什么不重要,写在人物段就是人物。

## 二、每类资产的设计要点(写什么才够)

好的参考图来自完整的描述。每类至少覆盖以下维度:

### 人物 Character
- **身份**:姓名、角色定位(主角/反派/配角)、一句话人设。
- **外观**:年龄、性别、体型、脸型、发型发色、肤色/族裔。
- **服装**:主要造型、材质、配色;有多套造型分别列。
- **区分点**:标志性配饰/伤疤/习惯动作等,保证跨镜头一致。
- **气质神态**:性格外化的表情、姿态。

### 场景 Scene
- **地点定位**:是什么空间、在故事里的作用。
- **空间结构**:布局、主要陈设、纵深。
- **光线氛围**:时间(日/夜)、光源、明暗、情绪。
- **年代/地域痕迹**:让场景可信的细节。
- **注意**:场景图里**不放主要人物**。

### 道具 Prop
- **物件本体**:是什么、材质、年代、磨损程度。
- **构图**:白底三视图或清晰单体,便于后续引用。
- **故事意义**:这个道具在剧情里的作用(影响细节设计)。

### 插入 Insert
- **聚焦细节**:特写的是哪一处、要看清什么。
- **构图**:微距/证据式,主体清晰居中。
- **光线**:克制写实,服务于"看清细节"。

## 三、文档格式规范(怎么写才能被正确解析)

### 3.1 一句话原则
用 `◆ XX卡` 分段;段内每个资产用**带圈序号 + 干净资产名 + (括注)**起头;
其余描述全部用 `· 字段：值` 写。

### 3.2 四条硬规则

**R1 段标题定类型**——必须 `◆` 开头且含「卡」字:
- 人物段 `◆ 人物卡`、场景段 `◆ 场景卡`、道具段 `◆ 道具卡`、插入段 `◆ 插入卡`。
- 全局说明(画风/调色板)用**不含「卡」字**的 `◆ 标题`(如 `◆ 全局画风锚`)。

**R2 序号行 = 一个新资产**——每个资产以 `①②③…` 或 `1. 2. 3.` 起头,序号后紧跟干净资产名。
- 名称遇第一个 `：，。；（` 截断,所以别名/代号放括号里安全。
- 反例:`① 一位70岁的老奶奶` → 名字变垃圾;正确:`① NANA` + 描述放 `·` 行。

**R2b 序号行必须带 `（…）` 括注**(最易漏、最关键):
- 每个资产名后跟一个 `（别名/定位/一句话）`。
- 原因:没有括注时,场景/道具/插入名若不以特定字结尾会被**静默丢弃**。带括注即可靠识别。
- 实测:`① 安全屋 SAFEHOUSE` 场景丢失;`① 安全屋 SAFEHOUSE（团队藏身处·夜）` 正确。

**R3 描述用 `· 字段：值`**——序号行以外的描述行一律用圆点起头,它们自动从属于当前资产,永不新建资产。
- 锁定生图提示词:用 `· 中文提示词：…` 和 `· EN prompt: …` 直接给,画面最可控。

## 四、生图提示词写法

系统会为每个资产自动生成提示词,但你也可**锁定**自己的提示词(推荐,画面最可控):
- 中文:`· 中文提示词：皮克斯风格3D渲染,约70岁和蔼老奶奶……竖屏9:16。`
- 英文:`· EN prompt: Pixar-style 3D render, a kindly grandmother… vertical 9:16.`
- 多套造型分多行:`· 中文提示词（日常态）：…`、`· 中文提示词（战斗态）：…`。

写提示词的要点:
- **主体身份**放最前(是谁/是什么)。
- **画风**统一(整片一致,建议在全局画风锚里定基调,单资产可微调)。
- **画幅**明确(竖屏 9:16 / 横屏 16:9)。
- **负向约束**(no watermark、no extra people 等)可选,系统会兜底。
- 只写剧本里有的信息,别让模型自由发挥导致跨镜头不一致。

## 五、提交前自检清单

- [ ] 每个类型段都有 `◆ …卡` 标题(含「卡」字)。
- [ ] 每个资产以 `①…`/`1.` 序号起头,序号后第一个词就是干净资产名。
- [ ] **每个序号行名字后都带 `（…）` 括注**(尤其场景/道具/插入,漏了会丢失)。
- [ ] 资产名里没有逗号/句号/冒号(别名放括号)。
- [ ] 所有描述都是 `· 字段：值` 行。
- [ ] 人物段只放人、场景段只放地点、道具段只放物件(靠段归属,不靠名字)。
- [ ] 全局说明用不含「卡」字的 `◆ 标题`。
- [ ] 需要精确画面的资产,给了 `· 中文提示词：` / `· EN prompt:`。

## 六、解析后的人工校对(拖拽重分类)

即使照规范写,偶尔仍可能有个别资产分类不理想(尤其剧本含"手机/照片"等词可能触发多余项)。
系统提供**生图前的人工校对**兜底:

1. 提取资产后进入**待确认**状态,资产按 人物/场景/道具/插入 四组展示。
2. 分错类的资产**直接拖拽**到正确分组,系统自动更新其分类与命名。
3. AI 认为可能分错的资产会**标黄提示**,供你核对参考(仅建议,以你拖拽为准)。
4. 多余的幽灵资产可拖走或用「设为不生成」排除。
5. 核对无误后点**「确认分类」**,分类锁定,才能开始生图。

要点:**确认前不能生图**;确认后分类即最终,视频配置全部引用校对后的正确分类。
拖拽只在生图前进行,不会破坏任何已有引用。

## 七、完整范例

```
◆ 全局画风锚
整体皮克斯3D,暖色调,竖屏9:16,浅景深。

◆ 人物卡 CHARACTERS
① NANA（阿格妮丝 / 代号 PURL）
· 一句话：人畜无害的烤饼干老太太,其实是头号杀手。
· 外观：约70岁,银白卷发挽成松髻,圆脸笑纹,金丝老花镜。
· 服装：芥末黄针织开衫 + 碎花围裙。
· 区分点：钛合金毛衣针,既是道具也是凶器。
· 中文提示词：皮克斯风格3D渲染,约70岁和蔼老奶奶,银白卷发,金丝眼镜,芥末黄开衫,竖屏9:16。
· EN prompt: Pixar-style 3D render, a kindly ~70-year-old grandmother, silver bun, gold glasses, mustard cardigan, vertical 9:16.

② DYLAN（迪伦·男主搭档）
· 外观：约25岁男性,黑色连帽衫,神情警惕。

◆ 场景卡 SCENES
① 安全屋 SAFEHOUSE（团队藏身处·夜）
· 定位：破旧城市公寓改的据点,家常与作战诡异共存。
· 光线氛围：夜,单盏暖黄台灯,其余压暗,紧张。

◆ 道具卡 PROPS
① 来电手机（老式翻盖机·剧情关键道具）
· 外观：老式翻盖机,屏幕显示未知号码,金属外壳有磨损。

◆ 插入卡 INSERTS
① 释放按钮特写（金属面板红色圆钮）
· 外观：金属面板上的红色圆钮,微微反光,微距证据式构图。
```
