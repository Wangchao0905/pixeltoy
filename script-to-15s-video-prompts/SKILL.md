# 15秒视频提示词生成

## 直接调用

在 Codex 中直接输入下面任一形式：

```text
$script-to-15s-video-prompts
把下面的剧本拆成视频生成任务，默认每段15秒；如果剧情需要，可将单段设置为4-30秒，并输出资产引用、起止状态和片段衔接：
[粘贴剧本或分镜]
```

如果当前任务已经在 PixelTale Short Drama 中完成了阶段确认，直接输入：

```text
$script-to-15s-video-prompts
读取当前 Short Drama 已确认的 characters、arc、scenes、dialogue，编译成唯一的视频生成包；默认15秒，支持4-30秒可变片段。
```

不要把同一段剧情再次单独生成一套平行视频 prompt；Short Drama 的阶段分镜是源数据，编译后的视频提示词包才是视频生成输入。

## 目标与硬约束

把脚本或剧情转成“短生成单元 + 后期重组”的视频制作方案。默认每个生成单元为15秒，允许根据动作完整度在4-30秒间调整；不要把整段剧情压进一个长 prompt。

- 每段必须有精确时间码，例如 `00:00-00:15`、`00:15-00:30`；每段时长必须在4-30秒内。
- 每段只承担一个清晰的叙事目的和一个主要动作，不在同一段塞入多个无关事件。
- 每段都要写起始状态、动作过程、结束状态；动作要有物理结果，不只写情绪形容词。
- 每段都要绑定资产、空间锚点、屏幕方向、光源方向和声音约束。
- 有锁定单段时长时，用 `ceil(总时长 / 单段时长)` 计算段数；未锁定时按动作完整度选择4-30秒，并保证最后一段不低于4秒。不能默默改变用户已锁定的时长策略。
- 没有真实资产文件或引用编号时，不要伪造 `@Image`、`@Audio`。使用 `资产 A01` 等概念 ID，并明确需要补齐素材。
- 未知信息标为“待定”或写成假设。只有在缺失信息会改变段数、人物身份、结局或画幅时才先提问；否则先产出带假设的可执行版本。
- 不要宣称某个视频模型支持未确认的参数、时长或引用语法。模型未指定时，输出通用自然语言 prompt。

## 何时使用

- 用户给出剧本、故事梗概、小说片段、分镜表或一组镜头，要求生成视频提示词。
- 用户希望每段固定15秒、希望使用4-30秒可变片段，或希望把长剧情拆成可以逐段生成再剪辑的镜头。
- 用户要求保持人物脸、服装、机甲、道具、场景、运动方向或光影连续。
- 用户需要提示词中包含摄影机、构图、动作、物理过程、环境声、音乐和片段间衔接。

不负责替用户杜撰真实项目的 prompt、EDL、资产文件或模型内部参数。若用户提供了参考项目分析，应把其中已验证的方法转成规则，而不是声称所有镜头都使用同一模板。

## 输入检查

先整理以下信息；缺失项写入“创作前提”而不是静默补成事实：

| 信息 | 用途 |
| --- | --- |
| 脚本或剧情 | 提取事件、因果、冲突、情绪变化和结局 |
| 目标总时长与单段策略 | 默认15秒；可指定4-30秒或允许按动作完整度选择 |
| 画幅、分辨率、目标模型 | 决定构图和可用的引用格式 |
| 角色、服装、道具、场景资产 | 建立跨段落一致性锚点 |
| 对白、旁白、音乐、音效 | 防止视频和声音指令互相冲突 |
| 风格和年龄分级 | 约束摄影、表演、色彩与内容边界 |

如果只有剧情一句话，先建立最小资产表和一条默认15秒样例；不要假装已经拥有角色表、场景图或音轨。

## 工作流

### PixelTale Short Drama 集成模式

当输入来自 PixelTale Short Drama 的阶段产物时，不要重新生成一套平行分镜。把现有阶段作为唯一源数据：

- `characters`：角色基础身份和可复用角色资产 ID。
- `arc`：集号、集尾钩子、人物选择和因果推进。
- `scenes`：场景、`character_engine_refs`、道具、视觉设定和 `shot_plan`。
- `dialogue`：场景对白、说话人、演绎和声音信息。

将这些字段编译成 `pixeltale_video_prompt_pack`。保留 `segmentDuration: {min: 4, max: 30, default: 15, policy}`，并为每个片段保留 `episode_number`、`scene_ids`、`source_shot_ids`、`asset_refs`、`start_state`、`action`、`end_state`、`transition_in`、`transition_out` 和 `prompt`。Short Drama 的分镜是叙事源数据，提示词包是唯一的视频生成任务输入；不要把两套完整 Prompt 分别提交给模型。

PixelTale 已有的“生成 → 校验 → 决定”、集级锁定和未锁定集重跑机制继续适用。上游场景或对白版本发生变化时，标记依赖它的提示词包为过期，只重编译和重生成未锁定片段。

### 1. 提取故事状态

把原文转成短表，不直接从文学修辞写 prompt。至少提取：

- 人物：身份、外观、服装、关系、当前身体和情绪状态。
- 场景：地点、时间、天气、关键地标、可通行方向和屏幕左右关系。
- 事件：触发事件、目标、阻碍、动作、反应、结果和下一段悬念。
- 视觉：主色、光源、色温、材质、能见度和镜头语法。
- 声音：对白、环境声、动作声、音乐进入/退出点。

每个事件写成“因为 A，所以 B，结果 C”。如果没有因果，先补出镜头需要的最小因果链，而不是堆关键词。

### 2. 建立资产圣经

为每个可重复出现的元素分配稳定 ID。资产 ID 贯穿所有段落，名称和描述不要每段改写。

| 类别 | 必须锁定 | 复杂状态的处理 |
| --- | --- | --- |
| 人物 | 脸型、发型、年龄感、体态、服装、主色、声音、表演基调 | 用独立状态资产锁定受伤、湿身、倒置、戴面罩等状态 |
| 机甲/道具 | 正面、背面、侧面、结构细节、尺度、材质、可动部件、武器或工具 | 为开舱、损坏、伸出武器、倒置等状态建立变体 |
| 场景 | 入口、柱体、窗、平台、地面纹理等地标；相对位置和运动路径 | 用布局参考图锁定空间，不把布局图自动当成 shot input |
| 光影 | 主光方向、色温、硬软、轮廓光、环境反射、雾和粒子 | 后续只允许按剧情改变强度或遮挡，不能无因改变方向 |

复杂物理优先在输入资产中预烘焙：例如倒置角色表、已损坏机甲表、已打开舱门状态。不要只靠 prompt 解释“角色要倒着但重力仍然正确”。操作机甲或道具时，必须描述操作过程、受力和结果，不能依赖图片下方的文字说明。

### 3. 计算视频段落

1. 先按触发、发展、转折、结果和悬念标记 beat。
2. 默认按15秒计算；如果用户锁定单段时长，计算 `段数 = ceil(目标总时长 / 单段时长)`，单段时长只能在4-30秒之间。
3. 将 beat 放入段落，优先在动作完成、视线改变、空间关系改变或情绪结果落地处切段。
4. 不要在连续动作的中间随意断开；若必须断开，使用动作匹配或声音桥，并写明下一段从哪个中间状态接续。
5. 每段内部按“建立状态—主要动作—结果/反应—交接钩子”检查；15秒段可参考 `00-03 / 03-10 / 10-13 / 13-15`，4-30秒段按比例调整，但不能省略起始和结束状态。

如果只给了剧情而没有总时长，默认先输出一个15秒单元，并列出是否扩展成4-30秒可变片段的假设；不要凭空生成几十段。

### 4. 更新连续性账本

每生成一段就更新下面的状态，下一段只从上一段的结束状态开始：

| 字段 | 记录方式 |
| --- | --- |
| 人物状态 | 位置、朝向、视线、姿势、服装完整度、伤势、手中物 |
| 场景状态 | 关键地标的相对位置、门/灯/烟/雨/碎片是否已经改变 |
| 动线 | 角色从哪侧进入、朝哪侧移动、镜头的屏幕方向 |
| 光线 | 主光来自哪一侧、色温、强度变化、阴影落向 |
| 声音 | 上一段末尾仍在延续的声音、对白最后一句、音乐状态 |
| 叙事事实 | 已发生事件、未解决目标、下一段必须继承的因果 |

用“左侧平台上的蓝色机甲，右臂受损，角色面向画面右侧”这类可检查描述，避免只写“保持一致”。

### 5. 生成六段式视频 prompt

每段 prompt 按以下顺序写；具体模型的特殊语法只能在用户提供或已验证时加入：

```text
[A 摄影/画质/风格前缀]
[B 非目标约束]
[C 参考资产绑定]
[D 主体、动作、情绪和物理结果]
[E 景别、角度、构图、镜头运动和关键时间节点]
[F 光影、环境、声音、音乐和段落衔接]
```

写作规则：

- A 只保留真正需要的摄影和视觉特征。避免同时写互相冲突的“手持、绝对稳定、长镜头、快速剪辑”。
- B 写可检查的禁止项：不新增角色、不更换服装、不改变机甲结构、不出现文字或 Logo、不发生无因的昼夜切换等。
- C 只引用真实存在的资产。概念资产写 `资产 A01（需生成）`，不要伪造文件编号。
- D 先写起始状态，再写连续动作，再写结束状态；使用“抓住、推开、滑落、撞击、停住”等动词，并写出重量、惯性、接触、遮挡或反作用。
- E 选择一个主要摄影机意图；给出景别、角度、主体在画面中的位置、镜头移动方向和最多几个关键节点。不要把整段剧情写成十几个镜头。
- F 用光源方向、色温、硬软、反射和环境介质描述光影；明确对白、纯音效或音乐是否存在；最后写本段如何交给下一段。
- 用短句和可执行名词，减少“史诗、震撼、梦幻、电影感”等无法检查的空泛形容词。
- 风格前缀不是必选项。只有项目真的有统一前缀才复用；不能把某个参考项目中的样本误写成全片固定前缀。

若用户要求英文 prompt，可保留输出表格和连续性账本为中文，单独把六段式 prompt 翻译成英文；资产 ID、时间码和物理状态不要翻译或改名。

### 6. 设计片段衔接

输出“建议衔接”，不要冒充真实剪辑点。优先选择能解释空间和动作连续性的方式：

- 动作匹配：上一段抬手、跳跃、开门或撞击，下一段从同方向和同一速度接上。
- 视线/方向匹配：保持角色视线和屏幕左右方向，反打前先明确轴线变化。
- 地标匹配：下一段保留上一段末尾可见的柱体、门、平台或光源，避免空间跳变。
- 声音桥：下一段画面切入前延续警报、脚步、机械摩擦或对白尾音。
- 光影匹配：沿用主光方向、色温和阴影逻辑；剧情需要改变时写出遮挡或光源事件。
- 对比性剪辑：只有在主题需要时使用静/动、冷/暖、远/近的突变，并标明这是有意的对比而非连续动作。

每段至少写：`从上一段继承什么`、`本段最后留下什么`、`下一段从哪里接`。没有公开 EDL 或音轨时，写“建议”而不是精确到帧的断言。

## 标准输出结构

按以下顺序交付，用户要求简短时也至少保留时间码、提示词和连续性字段：

1. **创作前提**：目标时长、画幅、模型、风格、声音，以及所有假设和待定项。
2. **资产圣经**：稳定 ID、外观锚点、状态变体、场景地标和光影基线。
3. **故事 beat 表**：每段的叙事目的、冲突、动作和结果。
4. **视频段落总表**：严格列出每个时间码、段落时长、主动作、起始/结束状态和建议衔接。
5. **逐段提示词**：每段一个可复制 prompt，附真实资产引用或概念资产说明。
6. **连续性账本**：按段记录人物、场景、动线、光线、声音和叙事事实的继承变化。
7. **剪辑与声音建议**：动作匹配、声音桥、硬切或对比剪辑的理由。
8. **质检结果**：指出未解决的资产、物理、模型语法、时长或版权问题。

逐段模板见 [references/prompt-schema.md](references/prompt-schema.md)。需要输出多个项目或大量段落时，先读该参考文件，再严格复用其字段名。

## 交付前检查

- [ ] 每个时间码在4-30秒范围内；若采用固定15秒或用户锁定时长，最后的非整除段明确标出留白/延长/提前引入。
- [ ] 每段只有一个主要叙事目的，且有起始状态、动作过程、物理结果和结束状态。
- [ ] 所有重复人物、机甲、道具和场景都有稳定资产 ID；没有凭空出现的 `@Image` 或 `@Audio`。
- [ ] 每段写清空间地标、相对位置、运动方向和镜头轴线。
- [ ] 人物脸、发型、服装、体态、道具持握和受伤状态没有无因变化。
- [ ] 主光方向、色温、阴影和环境介质跨段落连续；变化有剧情触发。
- [ ] 相邻段落至少有一种明确衔接：动作、视线、地标、光线或声音。
- [ ] 对白、音乐和纯音效约束不冲突；没有把需要后期完成的混音假装成已存在音轨。
- [ ] Prompt 是可执行动作描述，不是剧情摘要；没有用风格形容词替代摄影和物理信息。
- [ ] 没有声称已看到用户未提供的资产、EDL、模型参数或真实项目内部资料。

常见失败包括：把长剧情塞进一个 prompt、每段重新描述人物导致漂移、让布局图承担镜头输入、只写“保持电影感”、忽略动作惯性和接触结果、在没有音轨时伪造节拍点。发现这些情况时，回到资产圣经和连续性账本修正，不要继续叠加形容词。
